# 평가 보고서

> 평가일: 2026-08-02 · 평가 엔진: 1.1.0 · 데이터셋: `evaluation/datasets/official_core_cases.json`

## 1. 평가 범위와 해석 원칙

이 보고서는 저장소의 공개 법령 corpus를 대상으로 한 **검색·유보 평가**다. `LAW_RAG_LLM_PROVIDER=deterministic` 모드에서 실행했으며 외부 생성형 LLM을 호출하지 않았다. 따라서 인용 정확도와 `expected_answer_points` 기반 생성 답변 완결성은 이번 결과에 포함하지 않으며, 검색 지표를 생성 품질로 표현하지 않는다.

평가셋은 49개 문항, 8개 유형, 3개 난이도로 구성된다. 각 문항의 gold 법률 ID와 조문은 로컬 corpus 존재 검증을 통과했다.

### 평가 용어와 판정 단위

- **corpus**: 검색 대상으로 수집·정규화해 저장한 법령 조문 집합이다.
- **gold 근거**: 문항별로 사전에 지정하고 공식 원문과 대조한 정답 법률·조문이다.
- **상위 K개**: 평가 시 검색기가 반환한 앞쪽 K개 후보를 뜻한다. 이 보고서의 Hit@5·Recall@5와 실패 분류에서는 주로 K=5를 사용한다.
- **유보**: 근거 또는 정보가 부족하다고 판단해 확정적인 근거 답변을 생성하지 않는 동작이다.
- **진단 플래그**: 통과·실패를 단독으로 결정하는 최종 판정이 아니라, 검색 결과의 특정 품질 문제를 별도로 추적하기 위한 표시다.

검색 평가는 정답 조문의 회수 여부와 순위를 측정한다. 생성 답변의 문장별 근거 연결(Grounding)과 인용 검증(Citation Validation)은 별도 생성 평가 대상이며 이번 49문항 검색 전용 결과에는 포함하지 않는다.

## 5. 오류 유형

| 오류 유형 | 건수 | 판정 기준 |

`retrieval_miss`는 정답 회수 여부, `wrong_top1`은 정답의 검색 순위, `over_retrieval`은 정답 외 후보의 동반 반환을 진단한다. 세 유형은 관찰하는 문제가 다르며 한 문항에 둘 이상이 동시에 기록될 수 있다. 특히 `over_retrieval`은 기존 통과 판정과 독립적인 진단 플래그이므로 통과 문항에도 붙을 수 있다. 검색 전용 실행에서는 `unsupported_citation`과 `incomplete_answer`가 산출되지 않는 것이 정상이다. 이번 데이터의 gold가 대부분 단일 조문이므로 `under_retrieval`도 발생하지 않았다.

### 판례 연결 조문 정합성 가드

위 이행불능 사례는 단순 인용 유무 검증만으로 발견하기 어려운 `관련성 실패`다. v4.13.3부터 검증 판례가 연결 조문을 제공하고 법령 Top-1이 그 집합에 포함되지 않으면 법령 결과를 직접 근거로 승격하지 않는다. 검색 결과 자체는 실패 분석을 위해 보존하고 화면에서 `검색 후보`로 표시한다. 이 가드는 검색 순위가 개선되었다는 의미가 아니며, 부정확한 Top-1이 생성 답변으로 전파되는 것을 차단하는 안전장치다.

v4.13.4에서는 위 안전장치 다음 단계로, 검증 판례의 `related_statutes` 가운데 공식 corpus에 본문이 존재하는 조문을 `precedent_linked` 후보로 보강했다. `precedent_linked`는 일반 검색 점수로 찾은 결과가 아니라 판례에 기록된 관련 조문 정보를 통해 추가된 후보라는 뜻이다. 이행불능 문항에는 민법 제535조·제537조, 불안의 항변권 문항에는 제536조, 이행최고 후 해제 문항에는 제2조·제544조가 상단에 제시된다. 이는 BM25 Top-1 개선으로 집계하지 않으며, 판례가 제공한 검증된 연결 관계를 별도 provenance로 표시한다. 여기서 provenance는 각 후보가 일반 검색과 판례 연결 보강 중 어느 경로에서 제시됐는지 나타내는 출처·처리 경로 정보다.

## 8. 개선 전후 비교

기존 8개 공식 문항 결과와 이번 49개 결과는 문항 구성과 난이도가 달라 직접적인 성능 전후 비교로 사용하지 않는다. 이번 결과를 확장 평가셋의 최초 기준선(baseline)으로 고정하고, 이후 동일한 49개 데이터와 동일한 corpus에서 검색기 변경 전후를 비교한다.

판례 연결 보강은 일반 검색 랭킹과 분리된 provenance 기반 후보 확장이므로, 대표 판례 문항에 한해 같은 입력·corpus·Top-3 조건으로 다음과 같이 비교했다.

| 질문 | v4.13.3 Top-3 | v4.13.4 Top-3 | 관찰 |
| --- | --- | --- | --- |
| 원시적·후발적 이행불능 | 제538조·제539조·제537조 | **제535조·제537조**·제538조 | 판례 연결 조문이 두 시점의 핵심 규범 근거를 보강 |
| 불안의 항변권 | 제542조·제433조·제776조 | **제536조**·제542조·제433조 | 제536조 제1항·제2항을 하나의 조문 카드로 회수 |
| 이행최고 후 계약해제 제한 | 제546조·제544조·제400조 | **제2조·제544조**·제546조 | 신의칙과 이행최고 조문을 판례 연결 provenance로 보강 |

공식 법령 평가 49문항의 일반 검색 지표는 v4.13.3과 v4.13.4에서 동일했다(Top-1 34.88%, Hit@5 62.79%, Recall@5 62.79%, MRR 0.4465). 따라서 위 결과를 전체 BM25·시맨틱 검색 성능 향상으로 과장하지 않고, 검증 판례가 존재하는 해석 문항의 근거 회수 개선으로 한정한다.

우선 개선 대상은 다음과 같다.

1. 유사 조문 구별을 위한 법적 행위·목적 기반 ontology constraint 강화
2. 제3자 제공/수집·이용, 해고예고/서면통지 같은 hard negative 쌍 보강
3. 유보 임계값을 검색 점수 하나가 아니라 의도 일치도·gold 후보 간 격차와 결합
4. 시점 평가를 위해 과거 버전 corpus와 개정 전후 gold 문항 추가
5. 생성 평가 문항을 별도 실행해 인용 정확도와 정답 포인트 완결성 측정

## 9. 재현 방법

```bash
python tools/validate_evaluation_dataset.py

LAW_RAG_LLM_PROVIDER=deterministic python -m law_rag.benchmark \
  --dataset evaluation/datasets/official_core_cases.json \
  --output evaluation/reports/official_49_v4134.json \
  --fail-under 0 \
  --no-log-failures --json

python tools/render_evaluation_report.py \
  --input evaluation/reports/official_49_v4134.json \
  --output docs/EVALUATION_REPORT.md \
  --evaluated-on 2026-08-02
```

실제 외부 LLM 생성 평가를 수행할 때에는 provider·model·prompt version·temperature와 실행 시점을 별도로 기록하고 검색 평가 결과와 분리한다.
