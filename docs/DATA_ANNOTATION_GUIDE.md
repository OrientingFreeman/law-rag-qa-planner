# 법률 AI 평가 데이터 작성·정제·검수 가이드

## 1. 목적과 적용 범위

이 문서는 `evaluation/datasets/official_core_cases.json`의 평가 문항을 여러 작업자가 같은 기준으로 작성·검수하기 위한 작업 규정입니다. 평가 대상은 저장소에 적재된 공개 법령 corpus이며, 문항 수를 늘리는 것보다 서로 다른 실패 가능성을 분리해 측정하는 것을 우선합니다.

평가 데이터의 역할은 다음 세 가집니다.

1. 질문과 정답 조문의 연결 품질을 측정합니다.
2. 검색·유보·시점·인용 실패를 재현 가능한 형태로 기록합니다.
3. 모델 또는 검색기 변경 전후의 성능을 같은 기준으로 비교합니다.

이 데이터셋은 법률상담 정답집이 아닙니다. corpus에 존재하지 않는 법령, 판례, 행정해석은 확인 없이 정답으로 추가하지 않습니다.

### 기본 용어

| 용어 | 의미 |
| --- | --- |
| corpus | 평가와 검색의 대상이 되는 수집·정규화된 법령 조문 집합 |
| gold 조문 | 평가 문항별로 사전에 지정하고 공식 법령 원문과 대조한 정답 법률·조문 |
| 정답 포인트 | 생성 답변이 포함해야 하는 최소한의 독립된 의미 단위 |
| 유보 | corpus 범위나 질문 정보가 부족해 확정적인 근거 답변을 생성하지 않는 동작 |
| 직접 근거 | 질문의 핵심 법률효과를 직접 규정하는 조문 |
| 보조 근거 | 직접 근거의 정의·절차·예외 등을 이해하는 데 도움을 주지만 결론을 독립적으로 규정하지 않는 조문 |

gold는 현재 검색기가 잘 찾는 조문이 아니라 공식 원문과 질문의 법률관계를 기준으로 선정합니다. 검색기가 실패했다는 이유로 gold를 검색 결과에 맞춰 변경하지 않습니다.

## 2. 작업자 역할과 검수 흐름

| 역할 | 책임 |
| --- | --- |
| 작성자 | 공식 법령과 corpus를 대조해 초안을 작성하고 모든 필드의 근거를 기록합니다. |
| 1차 검수자 | 질문의 명확성, gold 조문, 정답 포인트, 유보 여부를 독립적으로 확인합니다. |
| 최종 승인자 | 중복·누수·난이도 편향과 전체 분포를 확인하고 pass/revise/reject를 판정합니다. |

가능하면 작성자와 1차 검수자를 분리합니다. 동일인이 검수할 때에는 작성 직후가 아니라 별도 세션에서 원문을 다시 확인합니다.

```text
공식 출처 확인 → corpus 존재 확인 → 문항 초안 → gold/포인트 작성
→ 독립 검수 → 스키마·참조 검증 → 시험 실행 → 최종 판정
```

## 3. 필드 작성 규칙

### `case_id`

- 영문 소문자, 숫자, 하이픈으로 고유하게 작성합니다.
- 법률 또는 영역, 핵심 쟁점이 드러나야 합니다. 예: `labor-dismissal-writing`.
- 질문 문구가 바뀌더라도 평가 의도가 같으면 ID를 유지합니다.
- gold 조문이나 평가 의도가 달라지면 새 ID를 만듭니다.

### `question`

- 실제 사용자가 입력할 수 있는 자연스러운 한국어 한 문장으로 작성합니다.
- 정답 조문명을 그대로 노출하는 직접 검색형과 일상어 표현을 의도적으로 구분합니다.
- 하나의 문항에서 검증하려는 실패 가능성을 설명할 수 있어야 합니다.
- 사실관계를 추가하면 답이 바뀌는 문항은 필요한 사실을 질문에 포함하거나 모호 문항으로 분류합니다.
- 정답 내용을 질문 속에 그대로 복사하지 않습니다.

### `category`

다음 값 중 하나만 사용합니다.

| 값 | 검증 목표 |
| --- | --- |
| `direct_statute_retrieval` | 명시적인 법률 질문에서 정답 조문 검색 |
| `lay_to_legal_mapping` | 일상어를 법률 개념과 조문으로 변환 |
| `similar_provision_disambiguation` | 표현이 유사한 인접 조문·타 법률 조문 구별 |
| `multi_requirement` | 원칙·요건·예외 등 복수 요소의 동시 회수 |
| `ambiguous_question` | 필수 사실이 없는 질문에 대한 추가정보 요청·유보 |
| `abstention` | corpus 범위 밖 질문에 대한 유보 |
| `temporal_revision` | 질문 기준일과 조문 시행일의 일치 여부 |
| `false_premise` | 존재하지 않는 조문 또는 잘못 결합된 법률명·전제 교정 |

두 범주가 겹치면 가장 중요한 단일 실패 원인을 기준으로 선택하고, 보조 의도는 `annotation_note`에 적습니다.

### `difficulty`

| 값 | 기준 |
| --- | --- |
| `easy` | 질문 표현과 조문 제목·핵심어가 직접 대응하고 정답이 단일 조문입니다. |
| `medium` | 일상어 매핑, 인접 조문 구별 또는 예외 확인이 필요합니다. |
| `hard` | 복합 요건, 잘못된 전제, 시점 판단, 여러 후보 법률 구별이 필요합니다. |

모델의 현재 성공률을 보고 난이도를 사후 변경하지 않습니다. 난이도는 문항 자체의 법률·언어적 요구를 기준으로 정합니다.

### `expected_law_id`와 `expected_article_nos`

- 저장소 corpus의 `law_id`, `article_no` 값을 그대로 사용합니다.
- 정답이 있는 문항에서는 두 필드를 함께 채웁니다.
- 유보 문항에서는 `expected_law_id: null`, `expected_article_nos: []`로 둡니다.
- 조문 번호 표기는 corpus 형식인 `제15조`, `제22조의2`를 따릅니다.
- 정답 조문이 여러 개라면 모두 직접 근거인지 확인합니다. 단순 참고 조문은 gold 목록에 넣지 않습니다.

### `expected_answer_points`

- 생성 답변이 포함해야 하는 최소 의미 단위를 문자열 배열로 작성합니다.
- 각 항목은 하나의 독립된 명제만 담습니다.
- 조문 전체를 복사하지 않고 결론, 핵심 요건, 예외, 시점 중 필요한 내용을 요약합니다.
- 질문에 답하는 데 필요하지 않은 학설·판례·실무 조언을 넣지 않습니다.
- 수치, 기간, 연령, 주체가 핵심이면 반드시 별도 포인트로 명시합니다.
- 유보 문항은 유보 사유와 추가로 필요한 정보를 포인트로 작성합니다.

좋은 예:

```json
[
  "원칙적으로 30일 전에 해고를 예고한다.",
  "예고하지 않으면 30일분 이상의 통상임금을 지급한다.",
  "법정 예외가 있는지 구분한다."
]
```

나쁜 예: `"근로기준법 제26조를 정확히 설명합니다."` — 채점 가능한 의미 단위가 없습니다.

### `expected_abstain`

- 시스템이 근거 답변을 생성하지 않고 범위·정보 부족을 명시해야 하면 `true`로 둡니다.
- 단지 질문이 어렵거나 검색기가 현재 실패한다는 이유로 `true`를 부여하지 않습니다.
- 잘못된 전제라도 corpus의 확정 근거로 교정할 수 있으면 `false`다.
- 유보와 추가정보 요청은 가능하지만, 존재하지 않는 사실을 추정한 답변은 허용하지 않습니다.

### Agent 안전성 필드

기존 필드와 같은 의미를 중복 생성하지 않습니다. 신규 경계 사례는 다음 선택 필드를 사용하며, 이전 문항은 기본값으로 계속 읽을 수 있습니다.

| 필드 | 작성 기준 |
| --- | --- |
| `expected_outcome` | `answer`, `request_facts`, `abstain` 중 기대되는 최종 결과 |
| `required_evidence_ids` | 결론에 반드시 필요한 corpus 근거 ID. 유보 사례는 빈 배열 가능 |
| `required_facts` | 답변 전 추가로 확인해야 할 사실 목록 |
| `failure_tags` | 재현하려는 실패 유형. 검색 결과에 맞춰 사후 변경하지 않음 |
| `dataset_version` | 문항이 속한 데이터셋 버전 |

`expected_abstain`은 하위 호환성을 위해 유지합니다. `expected_outcome`이 `abstain`이면 두 값이 모순되지 않아야 합니다. 존재하지 않는 조문은 정상 corpus나 법령 관계 데이터에 추가하지 않고 부정 테스트 질문에만 둡니다.

현재 12개 안전성·경계 사례는 존재하지 않는 조문, 시점 불명확, 필수 사실 누락, 충돌 근거, corpus 밖 질문, 비법률 질문, 과도한 범위, 잘못된 인용, 다중 적용 경로와 개정 전후 혼동을 대표합니다.

### `annotation_note`

- 이 문항이 검증하는 실패 가능성과 gold 선정 이유를 한두 문장으로 기록합니다.
- 정답 본문의 반복이 아니라 검수자가 판단을 재현하는 데 필요한 설명을 적습니다.
- 유사 조문을 배제했다면 그 조문과 배제 이유를 적습니다.

## 4. 정답 조문 선정 기준

### 직접 근거

질문의 법률효과, 요건, 의무, 권리 또는 기간을 직접 규정하는 조문입니다. 답변 결론이 이 조문 없이 성립하기 어렵다면 직접 근거입니다. `expected_article_nos`에는 원칙적으로 직접 근거만 넣습니다.

### 보조 근거

정의, 절차의 상세, 예외의 구체화, 관련 제재처럼 직접 근거를 해석·적용하는 데 도움을 주지만 질문의 결론을 독립적으로 규정하지 않는 조문입니다. 보조 근거는 검색 결과로 허용할 수 있으나 gold 조문 수를 부풀리기 위해 넣지 않습니다.

예시:

- “개인정보를 제3자에게 제공할 수 있는가”의 직접 근거는 개인정보 보호법 제17조입니다.
- 개인정보 수집·이용의 일반 근거인 제15조는 질문에 따라 보조 근거일 수 있지만 제3자 제공의 gold를 대체하지 않습니다.

### 선정 절차

1. 공식 법령 원문에서 질문의 법률효과를 직접 규정하는 조문을 찾습니다.
2. `data/legal_corpus.json`에서 법률 ID와 조문 번호가 실제 존재하는지 확인합니다.
3. 질문 기준일이 있으면 `effective_from`, `effective_to`와 비교합니다.
4. 유사 후보 조문을 최소 하나 검토하고 배제 이유를 `annotation_note`에 남깁니다.
5. 정답 조문만 보아도 `expected_answer_points`를 뒷받침할 수 있는지 확인합니다.

## 5. 사실성·정확성·논리적 완결성 검수

### 사실성

- 법률명, 법률 ID, 조문 번호, 시행일이 공식 출처 및 corpus와 일치합니다.
- corpus에 없는 내용, 판례, 숫자, 예외를 추측하지 않습니다.
- 질문의 전제가 틀렸다면 전제를 그대로 정답으로 수용하지 않습니다.

### 정확성

- gold 조문이 질문의 핵심 법률효과를 직접 규정합니다.
- 수집·제공, 해고예고·서면통지, 책임 성립·손해 범위처럼 유사 개념을 구별합니다.
- `expected_answer_points`의 주체, 요건, 기간, 예외가 원문과 일치합니다.
- 질문 기준일에 시행되지 않은 현재 조문을 과거 정답으로 사용하지 않습니다.

### 논리적 완결성

- 결론만 있고 적용 요건이 빠지지 않았는지 확인합니다.
- 원칙을 적었다면 질문에 중요한 법정 예외도 포함합니다.
- 복합 질문의 각 하위 질문에 대응하는 정답 포인트가 있습니다.
- 유보 문항은 왜 답할 수 없는지와 무엇이 추가로 필요한지를 함께 제시합니다.

## 6. 모호·복합·잘못된 전제 문항 처리

### 모호한 질문

법률관계, 행위, 주체 또는 손해 원인이 없어 복수의 상충하는 답이 가능하면 유보합니다. `expected_answer_points`에는 필요한 추가 사실을 적습니다. 단순히 표현이 일상적이라는 이유만으로 모호 문항으로 만들지 않습니다.

### 복합 질문

- 하위 쟁점을 분리해 각각의 최소 정답 포인트를 작성합니다.
- 하나의 질문에 서로 무관한 법률문제를 억지로 합치지 않습니다.
- 여러 gold 조문이 필요하면 각 조문이 어느 하위 쟁점의 직접 근거인지 기록합니다.

### 존재하지 않는 조문·잘못된 전제

- 존재하지 않는 조문은 유사 조문으로 조용히 대체하지 않고 존재하지 않음을 밝혀야 합니다.
- 법률명과 조문 번호가 잘못 결합됐지만 올바른 법률을 corpus로 확정할 수 있으면 전제를 정정하고 답합니다.
- 정정할 근거가 불충분하면 유보합니다.

## 7. 법령 개정 시 데이터 갱신 절차

1. 공식 출처에서 공포일, 시행일, 개정·삭제 조문을 확인합니다.
2. ingestion을 실행하고 corpus 버전 및 `source_checked_at`을 갱신합니다.
3. 변경된 법률 ID·조문 번호를 참조하는 평가 문항을 검색합니다.
4. 질문 기준일이 없는 현행 문항의 gold와 정답 포인트를 새 조문에 맞춰 재검수합니다.
5. 과거 시점 문항은 당시 버전을 보존하며, 해당 버전이 corpus에 없으면 유보 문항으로 전환하거나 제외합니다.
6. 스키마·corpus 참조 검증과 전체 평가를 실행합니다.
7. 변경 전후 지표를 별도 보고하고, 데이터 변경과 모델 변경 효과를 섞지 않습니다.

검증 명령:

```bash
python tools/validate_evaluation_dataset.py
LAW_RAG_LLM_PROVIDER=deterministic python -m pytest tests/test_evaluation.py tests/test_benchmark.py -q
```

## 8. pass / revise / reject 판정

### PASS

다음 조건을 모두 충족합니다.

- 필수 필드와 허용값이 스키마에 맞습니다.
- gold 조문이 corpus와 공식 원문에 존재합니다.
- 질문과 gold 사이에 직접적인 법률 관계가 있습니다.
- 정답 포인트가 원문에 의해 뒷받침되고 논리적으로 충분합니다.
- 유보 여부와 난이도·범주를 다른 검수자가 재현할 수 있습니다.
- 기존 문항과 표현만 다른 사실상 중복이 아닙니다.

### REVISE

평가 의도와 근거는 유효하지만 다음 중 하나가 있는 경우입니다.

- 질문이 어색하거나 필요한 사실 하나가 빠졌습니다.
- 직접 근거와 보조 근거가 섞였습니다.
- 정답 포인트가 너무 포괄적이거나 예외가 누락됐습니다.
- 난이도 또는 범주가 규칙과 맞지 않습니다.
- `annotation_note`만으로 선정 판단을 재현하기 어렵습니다.

수정 후 전체 검증을 다시 실행합니다.

### REJECT

다음 중 하나면 데이터셋에 포함하지 않습니다.

- 공식 출처 또는 corpus에서 근거를 확인할 수 없습니다.
- 질문의 정답이 학설·사실판단에 따라 달라 단일 gold를 정할 수 없습니다.
- 현재 검색기 실패에 맞추기 위해 정답이나 유보 여부를 왜곡했습니다.
- 다른 문항과 동일한 실패 가능성만 반복하고 추가 진단 가치가 없습니다.
- 판례·법령 내용을 추측하거나 출처 없이 요약했습니다.

## 9. 최종 체크리스트

- [ ] 질문이 하나의 명확한 평가 의도를 가집니다.
- [ ] 범주와 난이도가 문항 자체를 기준으로 정해졌습니다.
- [ ] 법률 ID와 모든 gold 조문이 corpus에 존재합니다.
- [ ] 직접 근거와 보조 근거를 구분했습니다.
- [ ] 정답 포인트가 독립적이고 채점 가능한 최소 명제입니다.
- [ ] 시점 문항의 기준일과 시행일을 대조했습니다.
- [ ] 유보 여부가 현재 모델 성능이 아니라 정답 정책에 따라 정해졌습니다.
- [ ] 잘못된 전제를 그대로 수용하지 않습니다.
- [ ] `annotation_note`로 검수 판단을 재현할 수 있습니다.
- [ ] 스키마·참조 검증 및 회귀 테스트를 통과했습니다.
