# 지원서용 프로젝트 요약

## 프로젝트 한 줄 정의

한국 법령 전문성을 바탕으로 **LLM 평가 데이터를 직접 설계·정제·검수하고, 검색·유보 결과를 정량 평가해 실패 원인을 구조화한 Evidence-Grounded Legal AI 프로젝트**입니다.

## 파운데이션 모델 데이터 직무용 요약

한국 법령의 조·항·호 구조와 시행일을 보존한 corpus를 구축하고, 법률 질문에 대한 검색·생성·검증 파이프라인을 설계했습니다. 이후 프로젝트를 단순 RAG 구현에 머물지 않도록 49개의 공식 평가 문항으로 확장하고, 질문 유형·난이도·gold 조문·필수 답변 포인트·유보 여부·검수 메모를 구조화했습니다. 동일한 기준으로 데이터를 재생산할 수 있도록 작성·정제·검수 가이드와 JSON Schema를 마련하고, Top-1·Hit@K·Recall@K·MRR·유보·시점 지표 및 오류 유형별 실패 분석을 구현했습니다.

추가 수동 검수에서 원시적·후발적 이행불능 질문에 주변 조문이 Top-1으로 검색되는 관련성 실패를 발견했습니다. 인용 형식의 정확성과 법적 관련성을 분리해 `wrong_top1`·`over_retrieval`로 기록하고, 검증 판례의 연결 조문과 Top-1을 대조하는 정합성 가드 및 `precedent_linked` 후보 보강을 구현했습니다. 일반 검색 지표가 변하지 않았다는 점도 명시하여, 개선 효과를 판례가 존재하는 해석 문항의 근거 회수 개선으로 한정했습니다.

### 공고 업무와의 연결

|  | 프로젝트에서 수행한 작업 |
| --- | --- |
| 데이터 생성 및 정제 | 법률 질문 49개를 8개 평가 유형과 3개 난이도로 설계하고 중복·범위·정답 근거를 정제 |
| 논리적 완결성·사실성·정확성 검토 | 직접/보조 근거 구분, 정답 포인트 작성, 유보 정책, gold 조문 corpus 존재 검증 |
| 학습·평가 데이터 생성 | `case_id`, 질문, 유형, 난이도, gold 법률·조문, 정답 포인트, 유보 여부, 검수 메모를 구조화 |
| 모델 평가 결과 검토 | Top-1, Hit@5, Recall@5, MRR, 유보 정확도, 시점 유효성을 유형·난이도별 집계 |
| 심화 실패 분석 | 검색 누락, 잘못된 1순위, 과다·과소 검색, 잘못된 유보, 미지원 인용, 불완전 답변, 시점 오류 분류 체계 구현 |
| 한국어 자연어처리 | 일상어와 법률용어 매핑, 유사 조문 구별, 복합 질문 분해, 잘못된 전제와 모호 질문 처리 |

## 데이터셋 설계

### 8개 평가 유형

1. 직접 조문 검색
2. 일상어와 법률용어 매핑
3. 유사 조문 구별
4. 복합 요건 질문
5. 모호한 질문
6. 답변 유보 대상
7. 시점·개정 법령
8. 존재하지 않는 조문 또는 잘못된 전제

각 문항에는 다음 데이터를 기록했습니다.

- `case_id`, `question`, `category`, `difficulty`
- `expected_law_id`, `expected_article_nos`
- `expected_answer_points`, `expected_abstain`
- `annotation_note`, domain, 기준일, 검색 K

문항 수를 형식적으로 늘리기보다 수집·이용과 제3자 제공, 해고예고와 서면통지, 채무불이행 책임과 손해 범위처럼 서로 혼동하기 쉬운 법률 개념을 hard negative로 구성했습니다. corpus 범위 밖 질문과 잘못된 전제도 포함해 모델이 근거 없이 답하는 문제를 별도로 평가했습니다.

## 데이터 품질 관리 체계

### 작성·정제 기준

- 질문은 실제 사용자의 자연스러운 한국어로 작성
- gold에는 질문의 법률효과를 직접 규정하는 조문만 포함
- 정의·절차·관련 제재는 보조 근거로 분리
- 정답 포인트는 결론·요건·예외·수치를 독립된 최소 명제로 작성
- 현재 검색기가 실패한다는 이유로 gold나 유보 정답을 변경하지 않음

### 검수 및 판정

- JSON Schema로 필수 필드, 허용 유형, 난이도와 값 형식 검증
- 모든 gold 법률 ID·조문 번호가 실제 corpus에 존재하는지 자동 검증
- 사실성·정확성·논리적 완결성을 구분해 검수
- `pass / revise / reject` 판정과 법령 개정 시 갱신 절차 문서화

## 실제 평가 결과

2026-08-02, 49개 공식 평가셋을 외부 LLM 호출 없이 로컬 결정론 검색 모드로 재실행했습니다.

| 지표 | 결과 |
| --- | ---: |
| 전체 Pass | 26/49 (53.06%) |
| Top-1 Accuracy | 34.88% |
| Hit@5 | 62.79% |
| Recall@5 | 62.79% |
| MRR | 0.4465 |
| 답변 유보 정확도 | 77.55% |
| 제한적 시행일 유효성 | 100.00% |

이 결과는 확장 평가셋의 최초 기준선입니다. 기존 8개 문항과는 구성과 난이도가 달라 직접적인 개선 전후 수치로 표현하지 않았습니다. 생성형 LLM을 실행하지 않았기 때문에 인용 정확도와 정답 포인트 기반 답변 완결성은 `N/A`로 분리했습니다. 시행일 100%도 과거 법령 내용의 정답률이 아니라, 기준일 이후 시행 조문이 결과에 포함되지 않았는지를 확인한 제한적 지표입니다.

## 평가 결과에서 확인한 실패 패턴

- `retrieval_miss`: 16건
- `wrong_top1`: 12건
- `incorrect_abstention`: 11건
- `over_retrieval`: 27건 — 기존 pass와 독립적인 진단 플래그로 통과 문항에도 발생 가능

유형별로는 유사 조문 구별이 Hit@5 20.00%로 가장 취약했고, 일상어→법률용어 매핑은 Hit@5 81.82%로 상대적으로 안정적이었습니다. 이를 바탕으로 법적 행위·목적 기반 ontology constraint, 유사 조문 hard negative, 유보 임계값 개선을 다음 우선순위로 도출했습니다.

## 이 프로젝트가 보여주는 역량

- 법률 전문지식을 정형 데이터와 검수 규칙으로 변환하는 능력
- 한국어 질문의 의미 차이를 평가 유형과 gold 데이터로 구체화하는 능력
- 모델 결과를 단일 성공률이 아닌 검색·순위·유보·시점·인용 관점으로 분해하는 능력
- 낮은 수치와 실패 사례도 숨기지 않고 재현 가능한 개선 기준선으로 관리하는 태도
- 평가 데이터, 자동 검증, 실행기, 실패 로그, 보고서를 하나의 품질관리 흐름으로 연결하는 구현 역량

## 공통 3문장

한국 법령의 조·항·호 구조와 시행일을 반영한 근거 기반 RAG QA 시스템을 설계·구현했습니다. 49개 평가 데이터를 8개 유형으로 구성하고 gold 조문·정답 포인트·유보 여부를 구조화했으며, 검수 가이드와 자동 검증을 통해 데이터 품질 기준을 마련했습니다. 검색·유보 성능을 유형·난이도별로 분석하고 실패 사례를 자동 분류해 법률 지식을 검증 가능한 LLM 데이터·평가 파이프라인으로 전환했습니다.

## 법률 실무 직무용

법률 질문을 쟁점·주체·요건으로 구조화하고 관련 조문과 공식 출처를 함께 제시하는 시스템을 개발했습니다. 근거가 부족하면 답변을 유보하도록 설계해 법률 정보의 신뢰성을 우선했으며, 반복적인 법률 확인 업무를 표준화하는 가능성을 검증했습니다.
