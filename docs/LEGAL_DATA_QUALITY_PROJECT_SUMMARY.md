# 법률 데이터 품질 프로젝트 요약

## 한 문장 요약

공개 법령 원문을 조문 단위로 구조화하고, 법령용어–일상용어–근거 조문을
연결한 뒤 법령 제·개정 시 영향 범위와 데이터 오류를 추적할 수 있도록
검증·평가 체계를 구축한 프로젝트입니다.

## 프로젝트를 확장한 이유

처음에는 법령 RAG 검색과 근거 기반 답변 생성을 구현했습니다. 그러나
검색 실패를 분석하면서 답변 모델만 개선해서는 해결되지 않는 문제가
있음을 확인했습니다. 같은 일상 표현이 여러 법률 개념을 가리키거나,
실제 조문이더라도 질문과 관련성이 낮은 근거가 선택되고, 법령 시행일이
다르면 정답 자체가 달라질 수 있었습니다.

이에 프로젝트를 법령정보지식베이스의 구축·정제·갱신·평가 영역으로
확장했습니다. 법령용어와 일상용어를 무조건 동의어로 처리하지 않고
문맥상 대응어, 상·하위어, 관련 비동의어로 구분할 수 있는 데이터 구조를
마련하고, 모든 개념을 현재 코퍼스에 존재하는 법령·조문·원문 문서 ID와
연결했습니다.

## 실제 구현 결과

| 항목 | 구현·검증 결과 |
|---|---|
| 법령 코퍼스 | 4,833개 조·항·호 문서 |
| 대상 법령 | 개인정보 보호법·시행령, 전자금융거래법, 근로기준법, 민법 |
| 법령 지식개념 | 41개 |
| 용어 관계 | 법률용어, 일상용어, 관계 유형, 적용범위, 유효기간, 근거 문서 |
| 품질 검증 | 중복 개념, 존재하지 않는 조문·문서, 잘못된 유효기간 자동 검출 |
| 변경 영향 분석 | 추가·삭제·본문 변경·시점 메타데이터 변경 분류 |
| 영향 추적 | 변경 조문과 연결된 용어 개념 및 공식 평가 문항 자동 식별 |
| 실제 개정 처리 | 개인정보 보호법 제15조제1항제7호 신설 탐지, 영향 개념·평가 문항 각 1건 추적 |
| 개정 시점 평가 | 시행일 전날·당일 2/2 통과 |
| 검수·승인 통제 | 필수 검수 9/9 통과, 개정 분석 결과 해시·공식 출처·시행일·영향·테스트 증거를 확인해 pass/revise/reject 판정 |
| 최종 재현 검증 | 지식베이스·개정 분석·평가·검수 실행, 공식 데이터 검증, 회귀 테스트와 문서 수치 대조로 통합 검증 9/9 통과 |
| KB 전용 평가 | 30문항, 6개 유형, 3개 난이도 |
| 폐쇄형 평가 결과 | 개념 Top-1·조문 Precision/Recall·유보·제한적 시점 정확도 각 100% |

100% 결과는 등록 어휘를 이용한 폐쇄형 결정론 평가 결과입니다. 자유로운
한국어 질의의 의미검색 성능이나 생성형 AI의 법적 답변 정확도를 뜻하지
않습니다. 미등록 표현, 포괄적인 질문, 코퍼스 범위 밖 질문, 보유 법령
버전의 시행일 이전 질문이 의도대로 유보되는지도 평가에 포함했습니다.

## 법령 제·개정 업데이트 절차

1. 공식 출처에서 후보 법령 원문과 시행일 메타데이터를 별도 수집합니다.
2. 기준선과 후보 코퍼스를 `document_id` 단위로 비교합니다.
3. 추가·삭제·본문·시점 메타데이터 변경을 분류합니다.
4. 변경 조문에 연결된 법령용어와 일상용어 매핑을 추적합니다.
5. 영향받는 평가 문항의 기대 법령·조문·정답 포인트를 재검수합니다.
6. 지식베이스 검증과 전체 회귀 테스트를 통과한 뒤 기준선을 교체합니다.

전체 코퍼스의 기준선 manifest는 같은 코퍼스를 비교한 `no_changes`
무결성 점검입니다. 이와 별도로 개인정보 보호법 제15조제1항제7호가
2025년 10월 2일 신설·시행된 실제 개정 사례를 공식 개정 전후 본문으로
구성했습니다. 도구는 신설 조문 1개를 실질 변경으로 탐지하고,
`pipa_collection_use` 지식 항목과 `pipa-collection-basis` 평가 문항을
재검수 대상으로 추적했습니다.

시행일 전날인 2025년 10월 1일에는 신설 조문을 제외하고, 시행 당일에는
포함하는 두 경계 문항도 모두 통과했습니다. 이 결과는 해당 사례에
한정되며 일반적인 과거 법령 검색 정확도로 확대 해석하지 않습니다.

## 프로젝트에서 확인할 수 있는 역량

### 법령용어–일상용어 매칭

‘알바생→근로자’, ‘외주업체에 고객정보 맡기기→개인정보 처리위탁’처럼
일상 표현을 법률 개념에 연결하되, 계약 명칭이나 일상 표현만으로 법적
결론을 확정하지 않도록 적용 범위와 주석을 함께 관리했습니다.

### 법령정보지식베이스 등록·개선

각 개념에 안정적인 ID, 법령 ID, 조문 번호, 원문 문서 ID, 시행 시작일,
검수 상태를 부여했습니다. 신규 등록뿐 아니라 중복, 참조 단절, 유효기간
오류를 기계적으로 검출할 수 있습니다.

### 제·개정에 따른 업데이트

법령 원문이 바뀌면 검색 결과만 다시 만드는 것이 아니라, 영향을 받는
용어 매핑과 평가 정답을 함께 추적하도록 구현했습니다. 자동 도구는 영향
후보를 제시하고 최종 법률 판단은 공식 원문을 대조한 검수자가 수행하도록
역할을 구분했습니다.

### 생성형 AI 법령검색으로의 확장 가능성

지식베이스의 개념 ID와 근거 조문 연결은 검색 질의 확장, 검색 결과
재정렬, 답변 인용 검증에 공통으로 사용할 수 있습니다. 따라서 기반
데이터의 정확성을 유지하면서 향후 생성형 AI 법령검색 평가 데이터로
확장할 수 있습니다.

## 직접 확인 가능한 산출물

- `data/legal_knowledge_base.json`: 41개 법령 지식개념
- `tools/validate_legal_knowledge_base.py`: 참조·기간·중복 검증
- `tools/analyze_legal_kb_update.py`: 제·개정 변경 및 영향 추적
- `tools/run_k4_amendment_case.py`: 실제 개정 사례 비교·영향·시점 평가 실행
- `evaluation/datasets/legal_kb_cases.json`: KB 전용 평가 30문항
- `evaluation/datasets/amendment_temporal_cases.json`: 시행일 경계 평가 2문항
- `docs/LEGAL_KB_UPDATE_GUIDE.md`: 등록·검수·갱신 절차
- `docs/LEGAL_KB_QUALITY_REPORT.md`: 실제 폐쇄형 평가 결과
- `docs/AMENDMENT_IMPACT_REPORT.md`: 실제 개정 영향 분석 결과
- `docs/AMENDMENT_REVIEW_REPORT.md`: 검수 단계·판정 근거·승인 한계 기록
- `docs/LEGAL_KB_VERIFICATION.md`: 전체 품질관리 흐름의 통합 실행과 문서 수치 일치 검증

## 30초 설명

> 법령 RAG를 개발하면서 검색 품질은 모델뿐 아니라 법령용어, 일상용어,
> 근거 조문과 시행일 데이터의 정확성에 크게 좌우된다는 점을 확인했습니다.
> 그래서 4,833개 법령 문서를 기반으로 41개 법률 개념을 구조화하고,
> 모든 개념을 실제 조문과 원문 문서에 연결했습니다. 또한 법령이 바뀌면
> 영향을 받는 용어와 평가 문항을 추적하는 업데이트 도구와 검수 절차를
> 구현했습니다. 실제 개인정보 보호법 개정 사례에서는 신설 조문과 영향
> 항목을 찾아내고 시행일 전후 평가도 수행했습니다. 자동화 결과를 법률
> 판단으로 대체하지 않고, 검수자가 확인해야 할 대상을 빠르게 식별하는
> 데 초점을 맞췄습니다.

## 한계

- 법령 범위는 현재 4개 법률과 개인정보 보호법 시행령에 한정됩니다.
- 41개 개념은 전체 법령용어 사전이 아니라 검수 가능한 소규모 PoC입니다.
- 개인정보 보호법 제15조제1항의 실제 개정 전후 fixture를 보유하지만,
  해당 법률 전체의 과거 버전 코퍼스를 구축한 것은 아닙니다.
- 의미가 비슷하지만 등록되지 않은 표현은 유보하며, 향후 독립 주석자의
  블라인드 평가 데이터로 일반화 성능을 검증해야 합니다.
