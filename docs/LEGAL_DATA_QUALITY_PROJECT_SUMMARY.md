# 법률 데이터 품질 프로젝트 요약

## 한 문장 요약

공개 법령 원문을 조문 단위로 구조화하고, 법령용어–일상용어–근거 조문을
연결한 뒤 법령 제·개정 시 영향 범위와 데이터 오류를 추적할 수 있도록
검증·평가 체계를 구축한 프로젝트입니다.

## 프로젝트를 확장한 이유

처음에는 법령 RAG 검색과 근거 기반 답변 생성을 구현했습니다. 그러나
검색 실패를 분석하면서 답변 모델만 개선해서는 해결되지 않는 문제가
있음을 확인했습니다. 같은 일상 표현이 여러 법률 개념을 가리키거나,
실제 조문이더라도 질문과 관련성이 낮은 근거가 선택되고, 법령 시행일이
다르면 정답 자체가 달라질 수 있었습니다.

이에 프로젝트를 법령정보지식베이스의 구축·정제·갱신·평가 영역으로
확장했습니다. 법령용어와 일상용어를 무조건 동의어로 처리하지 않고
문맥상 대응어, 상·하위어, 관련 비동의어로 구분할 수 있는 데이터 구조를
마련하고, 모든 개념을 현재 코퍼스에 존재하는 법령·조문·원문 문서 ID와
연결했습니다.

100% 결과는 등록 어휘를 이용한 폐쇄형 결정론 평가 결과입니다. 자유로운
한국어 질의의 의미검색 성능이나 생성형 AI의 법적 답변 정확도를 뜻하지
않습니다. 미등록 표현, 포괄적인 질문, 코퍼스 범위 밖 질문, 보유 법령
버전의 시행일 이전 질문이 의도대로 유보되는지도 평가에 포함했습니다.

## 법령 제·개정 업데이트 절차

1. 공식 출처에서 후보 법령 원문과 시행일 메타데이터를 별도 수집합니다.
2. 기준선과 후보 코퍼스를 `document_id` 단위로 비교합니다.
3. 추가·삭제·본문·시점 메타데이터 변경을 분류합니다.
4. 변경 조문에 연결된 법령용어와 일상용어 매핑을 추적합니다.
5. 영향받는 평가 문항의 기대 법령·조문·정답 포인트를 재검수합니다.
6. 지식베이스 검증과 전체 회귀 테스트를 통과한 뒤 기준선을 교체합니다.

전체 코퍼스의 기준선 manifest는 같은 코퍼스를 비교한 `no_changes`
무결성 점검입니다. 이와 별도로 개인정보 보호법 제15조제1항제7호가
2025년 10월 2일 신설·시행된 실제 개정 사례를 공식 개정 전후 본문으로
구성했습니다. 도구는 신설 조문 1개를 실질 변경으로 탐지하고,
`pipa_collection_use` 지식 항목과 `pipa-collection-basis` 평가 문항을
재검수 대상으로 추적했습니다.

시행일 전날인 2025년 10월 1일에는 신설 조문을 제외하고, 시행 당일에는
포함하는 두 경계 문항도 모두 통과했습니다. 이 결과는 해당 사례에
한정되며 일반적인 과거 법령 검색 정확도로 확대 해석하지 않습니다.

## 프로젝트에서 확인할 수 있는 역량

### 법령용어–일상용어 매칭

‘알바생→근로자’, ‘외주업체에 고객정보 맡기기→개인정보 처리위탁’처럼
일상 표현을 법률 개념에 연결하되, 계약 명칭이나 일상 표현만으로 법적
결론을 확정하지 않도록 적용 범위와 주석을 함께 관리했습니다.

### 법령정보지식베이스 등록·개선

각 개념에 안정적인 ID, 법령 ID, 조문 번호, 원문 문서 ID, 시행 시작일,
검수 상태를 부여했습니다. 신규 등록뿐 아니라 중복, 참조 단절, 유효기간
오류를 기계적으로 검출할 수 있습니다.

### 제·개정에 따른 업데이트

법령 원문이 바뀌면 검색 결과만 다시 만드는 것이 아니라, 영향을 받는
용어 매핑과 평가 정답을 함께 추적하도록 구현했습니다. 자동 도구는 영향
후보를 제시하고 최종 법률 판단은 공식 원문을 대조한 검수자가 수행하도록
역할을 구분했습니다.

### 생성형 AI 법령검색으로의 확장 가능성

지식베이스의 개념 ID와 근거 조문 연결은 검색 질의 확장, 검색 결과
재정렬, 답변 인용 검증에 공통으로 사용할 수 있습니다. 따라서 기반
데이터의 정확성을 유지하면서 향후 생성형 AI 법령검색 평가 데이터로
확장할 수 있습니다.

### 결제기업 법무 질문으로의 적용

전자금융·개인정보·기술 지식재산 질문 12건을 추가해 거래내용 확인, 오류
정정, 약관 설명·변경, 분쟁처리, 처리위탁, 특허 공개, 직무발명과 업무상
프로그램 저작자 쟁점을 실제 근거 조문에 연결했습니다. 이는 계약관리나
출원관리 기능을 새로 만든 것이 아니라, 기존 Q&A와 폐쇄형 평가 구조가
기술기업의 사업 질문에도 적용되는지를 확인한 도메인 확장입니다.

구체적 사실관계 없이 출원 가능성이나 권리귀속을 자동 확정하지 않도록
공개 시점·직무 범위·계약 및 근무규칙 등 추가 확인사항을 주석에 기록했습니다.

폐쇄형 어휘 매핑과 실제 검색 성능을 혼동하지 않도록 같은 12개 영역 질문을
하이브리드 검색 파이프라인에서 별도로 실행했습니다. 초기 기준선의 검색
누락과 과도한 유보를 바탕으로 도메인 동의어·질의 확장 규칙을 보강했고,
특허 공개 질문은 신규성 원칙과 공지예외를 함께 검토하도록 gold 조문도
보정했습니다. 최종 12문항 모두 정답 조문을 Top-1에서 회수했지만,
Top-K에 추가 후보가 포함된 `over_retrieval`은 별도 진단으로 남겼습니다.

이어 같은 12개 쟁점을 법률용어가 포함된 기준 표현과 일상적인 업무 표현의
쌍으로 구성해 총 24문항을 평가했습니다. 보강 전에는 13/24, 표현쌍 1/12만
통과했으나 일반적으로 재사용 가능한 동의어와 질의 확장 규칙을 보강한 뒤
24/24, 표현쌍 12/12가 통과했습니다. Top-1은 95.83%, Hit@5와 Recall@5는
100%, MRR은 0.9722였습니다. 한 문항은 정답 조문을 Top-5에서 회수했지만
첫 순위가 아니었으므로 Top-1 안정성을 100%로 표시하지 않았습니다.

복수 법률 쟁점을 한 질문에 결합한 8문항에서는 초기 전체 검색이 필요한
조문을 모두 회수한 문항이 1/8에 불과했고, 유보 판단까지 포함한 통과 문항은
0/8이었습니다. 명시적으로 감지된 도메인별 검색 경로를 각각 실행해 결합하고,
개인정보 중심 온톨로지가 전자금융·IP 근거를 억누르지 않도록 경로 출처를
분리했습니다. 그 결과 8/8 통과, 전체 쟁점 회수율과 평균 쟁점 Recall@10
100%를 확인했습니다. 이 결과도 내부 설계 Top-10 검색 평가에 한정됩니다.

검색 성공이 곧 답변 완결성을 뜻하지 않으므로 같은 8문항의 답변 단계도
별도로 평가했습니다. 쟁점 탐지 Recall은 18.75%에서 100%, 답변 계획의 필수
인용 Recall은 87.50%에서 100%로 개선됐고, 최종 답변의 필수 인용 Recall과
인용 유효성은 100%를 유지했습니다. 문장 근거 연결률은 93.95%에서 93.52%로
소폭 낮아져 개선 수치로 해석하지 않으며 기준 80%는 충족했습니다. 결과는
내부 8문항과 오프라인 결정론적 생성기에 한정되며 외부 생성형 LLM의 법률
답변 정확도를 나타내지 않습니다.

필수 인용 Recall과 별도로 각 인용 문장이 어느 쟁점과 검색 근거에 연결되는지
평가했습니다. 근거 노드와 결속할 수 없거나 추론 경로에서 쟁점 귀속을 설명할
수 없는 후보는 최종 답변 계약에서 제외했습니다. 인용-근거 결속률은 85.83%에서
100%, 인용 문장의 쟁점 귀속률은 42.14%에서 100%로 개선됐으며 사용자 답변의
내부 영문 쟁점명을 한국어 제목으로 교체했습니다. 이 수치는 구조적 추적성에
한정되고 인용의 법률적 충분성을 자동 판정한 결과가 아닙니다.

법적 근거를 찾았더라도 사실관계가 부족하면 결론을 확정하지 않도록 쟁점별
확인 사실도 평가했습니다. 개인정보 유출·전자금융사고·거래기록·파기·약관·
분쟁과 기술 지식재산 쟁점에 안정적인 fact ID를 부여하고, 공개일·공개 범위·
비밀유지 여부·종업원의 직무·발명 경위·계약 및 근무규칙 등을 확인하도록
보강했습니다. 평균 핵심 사실 Recall과 쟁점별 사실 커버리지는 12.50%에서
100%로 개선됐고, 답변 계획 반영률과 조건부 조언 유지율도 100%였습니다.
이 결과는 내부 8문항에 사전 정의한 사실 항목의 회수 평가이며 개별 사건에
필요한 모든 사실이나 최종 법률 판단의 정확성을 보증하지 않습니다.

기존의 획일적인 계약서·고지 중심 문구 대신 쟁점별 후속 조치도 구조화했습니다.
특허 공개 통제·증빙 보존·출원 일정, 직무발명과 프로그램 작성 경위, 전자금융
사고 증거, 거래기록 보존표, 개인정보 분리·파기, 약관 버전과 분쟁 회신 이력을
각 쟁점의 검색 규칙과 원문 문서에 연결했습니다. 평균 실무 조치 Recall,
쟁점별 조치 커버리지, 조치-근거 결속률과 답변 계획 반영률은 12.50%에서
100%로 개선됐습니다. 이는 내부 8문항에 사전 정의한 조치의 생성 평가이며
실제 조직의 업무절차 적합성이나 법률적 충분성을 자동 보증하지 않습니다.

누락 사실과 실무 조치를 쟁점별로 결합하는 조건부 검토 구조를 추가했습니다.
중요 사실이 남아 있으면 최종 판단을 확정하지 않고, 각 쟁점의 확인 사실을
`핵심·중요·추가` 순서로 배열한 뒤 관련 조치와 검색 근거에 연결합니다. 내부
8문항에서 조건부 결론 표시율, 우선순위 사실 Recall, 쟁점별 핵심 우선순위
정확도, 사실–쟁점–조치 연결률과 연결 근거 결속률이 모두 100%였습니다.
이 결과는 사전 정의 ID와 순서를 이용한 결정론적 구조 평가이며 개별 사건의
실제 긴급도나 최종 법률 판단을 의미하지 않습니다.

## 30초 설명

> 법령 RAG를 개발하면서 검색 품질은 모델뿐 아니라 법령용어, 일상용어,
> 근거 조문과 시행일 데이터의 정확성에 크게 좌우된다는 점을 확인했습니다.
> 그래서 7,516개 법령 문서를 기반으로 49개 법률 개념을 구조화하고,
> 모든 개념을 실제 조문과 원문 문서에 연결했습니다. 또한 법령이 바뀌면
> 영향을 받는 용어와 평가 문항을 추적하는 업데이트 도구와 검수 절차를
> 구현했습니다. 실제 개인정보 보호법 개정 사례에서는 신설 조문과 영향
> 항목을 찾아내고 시행일 전후 평가도 수행했습니다. 자동화 결과를 법률
> 판단으로 대체하지 않고, 검수자가 확인해야 할 대상을 빠르게 식별하는
> 데 초점을 맞췄습니다.
