# Agent Workflow와 Execution Trace

## 1. 목적

일반적인 단일 RAG 호출은 질문을 받아 검색하고 답변을 반환하지만, 중간에 어떤 판단이 이루어졌고 왜 실패했는지 재현하기 어렵다. 이 프로젝트의 Agent Workflow는 기존 검색·추론·생성 엔진을 다시 구현하지 않고, 각 기능을 명시적인 실행 순서와 안전 정책으로 연결한다.

법률·금융·컴플라이언스·내부 규정처럼 근거와 적용 시점을 설명해야 하는 분야에서는 그럴듯한 답변보다 다음 질문에 답할 수 있어야 한다.

- 어떤 검색 전략을 사용했는가?
- 어떤 근거를 최종 답변에 사용했는가?
- 근거가 부족할 때 재시도했는가?
- 이전 시도와 무엇이 달라졌는가?
- 왜 답변·추가 사실 요청·보류 중 하나를 선택했는가?
- 최대 재시도 횟수를 지켰는가?

## 2. 10단계 실행 흐름

1. 질의 분석
2. 검색 전략 결정
3. 근거 검색
4. 근거 적합성 검증
5. 쟁점 및 적용 경로 구성
6. 답변 생성
7. 인용·근거 검증
8. 품질 판정
9. 제한된 재시도
10. 최종 답변 또는 보류

각 단계는 `execution_trace`에 상태, 시작·종료 시각, 소요시간, 입력·출력 요약, confidence, 검색 전략, 근거 ID, 경고, 실패 사유와 재시도 횟수를 남긴다.

기존 `reasoning_trace`는 법적 추론 단계와 근거 관계를 설명한다. 새 `execution_trace`는 시스템 실행의 상태 전이와 중단을 설명한다. 두 trace의 책임을 분리해 기존 API 의미를 변경하지 않았다.

## 3. 안전한 결과 유형

| 결과 | 의미 |
| --- | --- |
| `answered` | 검색·인용·grounding 검증 범위에서 답변 가능 |
| `needs_clarification` | 기준일·사실관계·검토 범위를 추가로 확인해야 함 |
| `abstained` | 근거 부족, 존재하지 않는 조문, 도메인 밖 질문 등으로 답변 보류 |
| `failed` | 예외 또는 실행 오류로 정상 종료하지 못함 |

답변 보류는 시스템 실패가 아니다. 근거가 부족한데도 결론을 생성하는 대신 한계를 명시한 안전한 결과다.

주요 중단 코드는 다음과 같다.

- `unknown_law_or_article`
- `temporal_uncertainty`
- `scope_too_broad`
- `out_of_domain`
- `insufficient_evidence`
- `unsupported_citation`
- `evidence_conclusion_conflict`
- `missing_required_facts`
- `retry_no_improvement`
- `retry_limit_exceeded`

## 4. 재시도 통제

기본 최대 재시도 횟수는 1회다. 첫 검색이 근거 부족으로 보류된 경우 검색 문서 수를 늘리고 query rewrite와 reranking을 적용해 다시 검색한다. Trace에는 이전·변경된 `top_k`, 보류 상태 변화와 `quality_improved`가 기록된다.

존재하지 않는 조문, 기준일 누락, 명백한 비법률 질문이나 지나치게 넓은 요청은 검색 문서 수를 늘려도 해결되지 않으므로 즉시 보류하거나 추가 확인을 요청한다.

61개 결정론 평가에서 재시도는 12건 발생했지만 품질 개선률은 0%였다. 따라서 현재 재시도는 성능 향상 성과가 아니라 반복 제한과 실패 재현을 증명하는 기능으로 해석한다.

## 5. API

```text
POST /agent/runs
GET  /agent/runs
GET  /agent/runs/{run_id}
```

프로세스 내 Trace 저장소는 최근 200개 실행을 보관한다. 서버 재시작이나 여러 worker 사이의 영속성은 제공하지 않는다. 실제 운영에서 장기 보관이 필요하면 파일 또는 DB 저장소 구현으로 교체해야 한다.

## 6. 적용 범위와 한계

- 새 Agent 프레임워크나 복잡한 멀티에이전트를 도입하지 않았다.
- 기존 `LawRagService`와 추론 엔진을 오케스트레이션한다.
- semantic 검색은 외부 embedding 모델이 아니라 기존 문자 n-gram 방식이다.
- 동기 실행이므로 전체 평가를 HTTP 요청으로 실행하면 요청을 오래 점유할 수 있다.
- 안전 정책은 제한된 평가 데이터로 검증했으며 모든 법적 사실 누락을 탐지한다고 보장하지 않는다.
